# اختبار تبديل حسابَي طالب على نفس المتصفح — #4 و#27

التاريخ: 24 أكتوبر 2026. اختبرنا نسخة العرض المحلية المنشورة عبر HTTPS Quick Tunnel
بمتصفح Chromium واحد وقاعدة العرض المنفصلة. أنشأ الاختبار طالبَين مؤقتين في
مجموعة لها درس منشور. لم يستخدم كلمات مرور حسابات خالد أو طلاب حقيقيين.

1. دخل الطالب A وفتح الشادوينج. وضع الاختبار تسجيلًا تجريبيًا في IndexedDB
   بنفس شكل التسجيل المحلي الذي تحفظه الواجهة، ثم أعاد فتح الصفحة وتأكد
   أن التسجيل ظهر له.
2. سجل A الخروج، وتأكد الاختبار أن جلسة API صارت غير مصادق عليها.
3. دخل الطالب B **في نفس المتصفح** وفتح الدرس نفسه. لم تظهر بطاقة تسجيلات
   A أو رابط صوت محلي `blob:`، وأعاد API رقم حساب B في بيانات الدرس.
4. لم تظهر أخطاء HTTP 500. النتيجة: `Same-browser account switch and
   recording isolation: PASS`.

الاختبار محفوظ في `tests/account-switch-e2e`. يحتاج `DEMO_DB_CONNECTION`
لقاعدة العرض المنفصلة و`DEMO_URL` لرابط Quick Tunnel الخاص بها، ونسخة
Playwright مثبتة في المشروع. يرفض أي عنوان ليس HTTPS على `trycloudflare.com`.
يشترط أن يكون للعرض درس منشور. بعد التشغيل يقفل حسابَي الاختبار ويُبقي
صفوفهما للمراجعة؛ لا يحذف حسابات أو ملفات.

هذا يثبت عزل **التسجيلات المحلية المعروضة ومسار الدرس** في هذه التجربة.
اختبارات الخادم المنفصلة تتحقق من `Cache-Control: no-store` للصوت ومن منع
طالب مجموعة أخرى من فتح صوت الدرس. لا يثبت الاختبار محو التسجيلات المخزنة
فعليًا في جهاز مشترك؛ حساب Windows آخر على الجهاز نفسه أو الوصول المباشر
إلى ملفات المتصفح موضوع مستقل عن واجهة الموقع.
