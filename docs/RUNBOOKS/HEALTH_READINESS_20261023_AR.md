# فحص صحة V2 — البند #12

التاريخ: 2026-10-23.

- `/health/live` يفحص أن عملية API تستطيع الرد فقط؛ لا يعتمد على SQL أوالصوت.
- `/health` يفحص الاتصال بقاعدة البيانات، وتهيئة تخزين الصوت، وإمكانية الوصول إلى حاوية الصوت الخاصة في Azure. الطلب لا يكتب ملفًا أوصفًا. يرجع `200` عند نجاح التبعيات و`503` عند فشلها، دون تفاصيل اتصال أوأسرار في الرد.
- الفحص له حد أربع ثوانٍ. يحتفظ الخادم بالنتيجة عشر ثوانٍ إذا نجح وثلاث ثوانٍ إذا فشل، حتى لا ينفذ استعلام SQL وطلب تخزين مع كل زيارة للرابط العام. الرد للمتصفح نفسه `no-store`.

اجتازت اختبارات `--health-check` أربع حالات: تخزين غير مضبوط، تبعيات سليمة مع إعادة استخدام نتيجة الفحص، تعطل التخزين، وتعطل قاعدة البيانات. فشل التبعيات التجريبية أعطى `503` بلا تفاصيل استثناء.

هذا الفحص يثبت وصول الخدمة إلى الحاوية الخاصة، لكنه لا يثبت أن الكتابة الجديدة ستنجح أوأن كل ميزات AI تعمل. يحتاج نشر Azure إلى فحص `/health` بعد ترحيلات قاعدة البيانات وضبط التخزين؛ إبقاء `/health/live` منفصلًا يمنع الخلط بين عمل العملية وجاهزية الخدمة.
