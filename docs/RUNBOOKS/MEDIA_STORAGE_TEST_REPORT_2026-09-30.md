التاريخ: 2026-09-30 UTC. استُعيدت الحزمة الأخيرة والتحقق من SHA-256 وملفات مصدرها قبل متابعة العمل. مصدر Git الأساسي `5aefba843dacd0e9392f1a88fba36b4c10915e24`. هذا التقرير خاص بالجولة الحالية في Linux معزولة؛ لا يستبدل الأدلة التاريخية لتشغيل جهاز خالد ولا يدّعي النشر على Azure.

## التغيير والنتيجة

تخزين WAV النهائية في Azure Blob Storage الخاصة منفذ وقابل للضبط، مع بقاء ملفات التطوير محلية. أزيل منع الإنشاء والنشر خارج Development عندما يكون التخزين الصحيح متاحًا، دون نقل المحرك أوالنموذج إلى الاستضافة. أضيف تحقق WAV كامل قبل الرفع، وتنظيف آمن للملفات الخاصة بالمحاولة، وحماية حالة نجاح SQL ثم فقدان الرد، وقراءة صوت مصرح بها تدعم Range وETag.

أُضيف اختبار حقيقي لمسار Admin Save → Publish → Student curriculum/audio/progress. يعمل بـAPI وIdentity وCSRF الفعلية في ASP.NET Core TestServer وSQLite مؤقتة ومحاكي Azurite محلي. **ليس API mock، وليس SQL Server أوAzure منشورة.** لا تطبيق migrations أونقل بيانات، ولا تعديل V1 أوالقواعد المعتمدة أونموذج/ترحيلات SQL.

## حالات API والتخزين الـ16

| الحالة | ما ثبت |
|---|---|
| 1. بنية WAV | رفض ملف مزور أوفارغ أوtruncated وقبول PCM حقيقية. |
| 2. إعداد Production | رفض القرص المحلي وHTTP وSAS وعنوان تخزين غير موثوق وإعداد credential متعارض. |
| 3. Blob خاصة وثابتة | SHA-256 وbytes صحيحة، قراءة قابلة للـseek، ورفض overwrite. |
| 4. الخصوصية | رفض الحاوية العامة وعدم إمكان قراءة الملف الخاص مباشرة بلا صلاحية. |
| 5. Identity + CSRF | anonymous `401` وStudent على authoring `403` وPOST بلا CSRF `400`، عبر endpoints الفعلية. |
| 6. GET audit | fingerprint بيانات كل الجداول وBlob keys/ETags/length لا تتغير عند القراءة. |
| 7. ثاني WAV غير صالح | `400` دون حفظ أول ملف أوصف درس. |
| 8. Save | `201` مع ملفات وmetadata حقيقية ودون نشر. إعداد التطبيق Production أثناء الاختبار. |
| 9. Save retry | نفس الطلب `200`، محتوى مختلف `409`، ولا درس أوصوت مكرر. |
| 10. Publish | طلب صريح `201` ثم إعادة `200`؛ الدرس يظهر في المنهج والجمل للطالب المسند. |
| 11. الصوت | full `200` بbytes مطابقة، `206` يعيد 44 byte المطلوبة، `304` دون تنزيل جسم Blob، و`416` للـrange غير الصالح. يظل GET بلا كتابة. |
| 12. عزل المجموعة | طالب مجموعة أخرى `404` وanonymous `401` قبل أي طلب Blob. |
| 13. التقدم | حفظ المرحلة والتكرار والتحديث يحتفظ بالنتيجة؛ إعادة نشر مجموعة بدأ تقدمها `409` دون تصفير. |
| 14. فشل الرفع الثاني | `503` وتنظيف ملفات المحاولة فقط، مع بقاء الدروس الأخرى وصوتها. |
| 15. فقدان الرد بعد commit | فشل محقون بعد نجاح SQL؛ تبقى ملفات الدرس، وإعادة الحفظ `200` دون تكرار. |
| 16. تخزين معطل وتشخيص | `503` دون صف درس؛ السجلات المفحوصة لا تحتوي password أوالنص أومفتاح التخزين. |

الـrange الصغير لا يجلب الملف كاملًا من التخزين: رصد اختبار HTTP النقل وحصره في buffer قراءة 64 KB. `304` يحتفظ بطلبات metadata اللازمة، مع صفر bytes لجسم الصوت من Blob. هذه قياسات هذه الحالة، وليست تقديرات لاتصال الاستضافة.

SQLite هنا لها تحويل DateTimeOffset داخل model customizer اختباري فقط حتى تعمل المقارنات الزمنية. لا تختبر هذه النتيجة أقفال SQL Server والتزامن الحقيقي أوmigrations. اتصال Azurite HTTP استُخدم عبر DI الاختباري؛ مصنع Production نفسه يرفض HTTP وloopback.

## عوائق صُححت أثناء الجولة

- التنزيل الافتراضي لمتصفح Playwright الحالي تعذر في البيئة. Chromium الكامل 134 لم يبدأ بسبب منع socket الخاص بـprocess singleton. نُزّلت headless shell لنفس Chromium من أرشيف Playwright الرسمي؛ أعيدت الحالات الثماني ونجحت دون تعديل assertions أوتعطيل اختبار. لا يعد هذا فحص إذن الاتصال المحلي في Chrome الحديث.
- التشغيل الافتراضي متعدد عمال MSBuild تعطل بسبب اتصالات العمليات المحلية. استخدم البناء عاملًا واحدًا و`UseSharedCompilation=false` دون تعديل كود التطبيق لتجاوز الفحص.
- أول تشغيل لاختبار المنهج قرأ اسم JSON قديمًا `lessons`؛ العقد الفعلي `items`. صُحح الاختبار وأعيدت المجموعة كاملة، ثم نجحت 16/16.
- dependency SQLite الاختبارية القديمة أظهرت advisory. جرى تثبيت bundle 3.0.5 وSQLite native 3.53.3 في **مشروع الاختبار فقط**؛ البناء النهائي بلا تحذيرات NuGet.
