# قراءة الطلاب أثناء إعادة نشر الدروس

التاريخ: 23 أكتوبر 2026. تحقق جزئي ضمن #25 و#7.

أضفنا فحص SQL Server محليًا مع API حقيقي داخل TestServer. ينشئ الفحص
30 مجموعة و10 دروس و3000 طالب و30 ألف محاولة، ثم يسجل دخول طالب واحد
من كل مجموعة. أثناء إعادة نشر كل المجموعات، يكرر الطلاب الثلاثون قراءة
`/api/student/learning/curriculum`. يقبل الفحص نسخة المنهج القديمة كاملة
أو نسخته الجديدة كاملة، ويرفض أي خلط بين معرف النسخة وبطاقات دروس نسخة
أخرى. وبعد اكتمال النشر، يتحقق من أن كل طالب يرى النسخة الجديدة.

| القياس في التشغيل الأخير | النتيجة |
| --- | ---: |
| القراءات المكتملة أثناء النشر | 9406 |
| أخطاء HTTP أو خلط النسخ | 0 |
| زمن القراءة P95 | 30 ms |
| زمن القراءة P99 | 43 ms |
| أبطأ قراءة | 1316 ms |
| زمن إعادة نشر 30 مجموعة | 13691 ms |
| سجلات المحاولات المنقولة | 30000 |

نجح أيضًا تشغيل سابق بالحمل نفسه: 9122 قراءة، P95 = 37 ms، وأبطأ قراءة
1028 ms. الأرقام تخص جهاز التطوير وقاعدة SQL محلية؛ لا تثبت أداء Azure
أو تحمل 3000 طالب متزامن. هذا الاختبار فيه **30 طالبًا قارئًا متزامنًا**
مع 3000 طالب مزروعين في قاعدة البيانات. الاختبار لا يحذف الملفات أو
بيانات الطلاب؛ يستخدم قاعدة الاختبار المعزولة نفسها.

ما تبقى ضمن #25/#7: قياس النمو بعد نشرات متكررة، وقياس بيئة الاستضافة
النهائية، ثم التعامل مع أي بطء يتجاوز المستوى المقبول هناك.
