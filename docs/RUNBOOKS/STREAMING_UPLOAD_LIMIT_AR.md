# اختبار حد رفع تسجيل الطالب المتدفق

حد ملف التسجيل 8 MiB، وحد الطلب الكامل 8 MiB + 128 KiB لبيانات نموذج الرفع. يُرفض الطلب الذي يعلن `Content-Length` أعلى من الحد قبل قراءة النموذج. ضُبط أيضًا حد الجزء داخل قارئ `multipart`؛ لذلك يُوقف الملف الكبير أثناء القراءة حتى عندما يرسل العميل الطلب على أجزاء من غير `Content-Length`، ويعيد HTTP 413.

التحقق في 23 أكتوبر 2026:

- نجح اختبار `--auth-rate-check` لطلب معلن الحجم وطلب متدفق مجهول الحجم على `TestServer`، وكلاهما عاد 413.
- نجح الطلب نفسه مباشرة على Kestrel الخاص بعرض الجهاز بعد تسجيل الدخول؛ عاد 413 برسالة التطبيق `recording_too_large`.
- عبر Quick Tunnel عاد الطلب 413 مرة، ثم 500 من وكيل Cloudflare في محاولات لاحقة برسالة `Network connection lost`، بينما بقي التطبيق المحلي سليمًا. لذلك **استجابة الرفع المتدفق عبر Quick Tunnel غير مستقرة** ولا تعتبر ناجحة بهذا الفحص. لم تحفظ هذه المحاولات ملفًا صوتيًا.

**المتبقي من البند #6:** حسم سلوك الوكيل العام مع الرفع المتدفق واختبار Azure بعد نشر هذا الإصلاح هناك. فرع `deploy/staging` لم يُحدَّث بهذا الإصلاح، فلا يصح اعتبار بيئة Azure مختبرة أو نشر الكود وحده قبل التحقق من ترحيلات قاعدة البيانات المطلوبة لبقية التعديلات.
