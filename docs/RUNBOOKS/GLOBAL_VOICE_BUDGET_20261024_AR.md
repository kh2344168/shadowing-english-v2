# حد إجمالي يومي لخدمات الصوت — استكمال #1 و#2

التاريخ: 24 أكتوبر 2026. كان الحد السابق لكل مستخدم فقط؛ مع كثرة الطلاب
كان مجموع استدعاءات مزود الصوت يمكن أن يزيد دون حد على مستوى الموقع.

أصبح حجز تحويل الصوت إلى نص وتوليد الصوت يفحص مجموع استخدام **كل الحسابات**
في يوم UTC نفسه، بالإضافة إلى حد المستخدم. الافتراضي 500 تحويل و100000 حرف
توليد في اليوم. يمكن ضبطه من إعدادات API:

- `VoiceBudget__GlobalDailyTranscriptions`: عدد التحويلات اليومي للموقع كله.
- `VoiceBudget__GlobalDailyCharacters`: حروف التوليد اليومية للموقع كله.

القيمة `0` توقف نوع الطلب تمامًا، من غير استدعاء مزود الصوت. يظل الحد
اليومي الفردي قائمًا. يستخدم SQL Server قفلًا مشتركًا بين نسخ التطبيق داخل
المعاملة قبل حساب المجموع، حتى لا تتخطى طلبات طلاب مختلفين الحد إذا وصلت
في اللحظة نفسها. لا يحتاج الإصلاح إلى ترحيل قاعدة بيانات.

التحقق: نجح بناء Release، واختبار SQLite للحدود الفردية والعامة وقيمة صفر.
في قاعدة SQL Server اختبار معزولة، أرسلنا طلبَي تحويل متزامنين لطالبين
مختلفين وفي الحصة طلب واحد فقط؛ نجح واحد ورُفض الآخر. تكررت النتيجة مع
طلبَي توليد صوت. قُفلت حسابات الاختبار بعده وبقيت الصفوف؛ لم تُحذف بيانات.

**هذا حد استهلاك، وليس سقف فاتورة بالجنيه**: سعر المزود ونوع النموذج
والخطة قد يتغيرون. الحجز يحدث قبل الاتصال بالمزود؛ الطلب الفاشل قد يستهلك
الحصة دون تكلفة فعلية، وهذا اختيار محافظ يمنع الإنفاق غير المقصود. إذا كان
الشرط عدم دفع أي مبلغ لخدمة الصوت، اضبط الحدين إلى `0` إلى أن تتأكد من
خطة المزود. تطبيق الإعدادات على Azure يحتاج نشر هذا الكود وضبط قيمها هناك.
