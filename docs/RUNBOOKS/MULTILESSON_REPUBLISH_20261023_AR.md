# إعادة نشر منهج متعدد الدروس

التاريخ: 23 أكتوبر 2026. تحسين جزئي ضمن #25 و#7.

كان ناشر الدرس المعتمد يرسل أمر نسخ محاولات مستقلًا لكل درس في كل مجموعة،
وأوامر إضافية لمراحل الدرس الذي تغير. أصبح يرسل أمر SQL واحدًا لكل مجموعة.
يربط الأمر معرفات الدروس القديمة بالجديدة عبر خريطة JSON محددة المعاملات،
وينقل محاولات المراحل التي بقي محتواها كما هو فقط. يظل النشر داخل معاملة
كل مجموعة، ويبقى تاريخ النسخ القديمة محفوظًا.

اختبرنا SQL Server محليًا بقاعدة اختبار معزولة ومخرج WhisperX حقيقي.
اختبار 30 مجموعة و10 دروس و3000 طالب و30 ألف محاولة نقل كل المحاولات
والتقدم إلى النسخ الجديدة. تحقق الاختبار أيضًا من أن محاولات **كل درس**
وصلت إلى الدرس الصحيح، لا من العدد الإجمالي وحده.

| الحمل | زمن الناشر | النتيجة |
| --- | ---: | --- |
| 10 مجموعات، 10 دروس، 300 طالب، 30 ألف محاولة، قبل جمع أوامر النسخ | 5071 ms | نجح |
| الحمل نفسه بعد التغيير، تشغيلان | 6081 و4325 ms | نجح |
| 30 مجموعة، 10 دروس، 3000 طالب، 30 ألف محاولة، بعد التغيير، تشغيلان | 9816 و11881 ms | نجح |

تختلف الأزمنة بين التشغيلات؛ لا تكفي هذه العينات لإثبات تحسن زمن ثابت.
التحسن المؤكد هو تقليل عدد أوامر نسخ المحاولات من أمر لكل درس/مرحلة إلى
أمر لكل مجموعة. نجحت أيضًا خمس حالات `--ai-publication-check`، وبناء
Release دون تحذيرات. لم يحذف الاختبار ملفات أوبيانات؛ أضاف بيانات اختبار
إلى قاعدة SQL المحلية المعزولة.

لا يغلق هذا البند #25/#7 كاملًا: يلزم قياس قراءة الطلاب بالتزامن مع النشر،
ونمو حجم قاعدة البيانات بعد نشرات متكررة، وقياس بيئة الاستضافة النهائية.
لم يُختبر هنا دخول 3000 طالب **في نفس اللحظة**.

إعادة الاختبار بعد تجهيز ملف manifest محلي للأداة:

```powershell
& .\.local\tools\dotnet-10.0.402\dotnet.exe run --project tests/ShadowingEnglish.MediaChecks/ShadowingEnglish.MediaChecks.csproj -c Release -- --processor-group-republish-load '<manifest path>' 30 100 1 10
```
