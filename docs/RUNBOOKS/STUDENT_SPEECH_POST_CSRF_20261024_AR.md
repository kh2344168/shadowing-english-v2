# حماية طلبات توليد صوت الطالب — استكمال #2

كان تشغيل صوت الكلمات وردود المحادثة يرسل GET، رغم أنه قد يحجز حصة يومية
ويستدعي خدمة توليد صوت مدفوعة. أصبح المساران يقبلان POST مع فحص CSRF قبل
الحصة أو المزود، وتستخدم الواجهة الطلب المحمي ثم تشغّل الصوت المستلم.

تلغي صفحة المحادثة تشغيل الرد المتأخر عند مغادرتها أو بدء التسجيل أو تغيير
الصوت، وتحرر رابط الصوت المؤقت عند انتهاء التشغيل. الطلب الذي وصل بالفعل
إلى المزود قد يظل له استهلاك؛ هذا الإصلاح لا يضيف سقف فاتورة عام.

التحقق: نجحت 30 حالة AI في الخادم، منها رفض GET ورفض POST بدون CSRF
للمسارين، وحماية ملكية محتوى الكلمات. نجح 23 اختبار واجهة للكلمات والمحادثة،
منها تشغيل الصوت عبر POST وتحرير الصوت عند الخروج وتجاهل الرد المتأخر.
لم تُستخدم خدمة صوت مدفوعة. يجب نشر الواجهة والـAPI معًا؛ الواجهة القديمة
التي ترسل GET تحتاج تحديث الصفحة بعد النشر.
