## النتيجة

الأداة المحلية وصفحة Admin ونقل نتيجة Shadowing إلى منشئ الدرس منفذة، مع تنزيل حزمة مرتبطة بالحساب والموقع، واستيراد ربط موجود، وإعدادات، وتقدم وإلغاء واستعادة متابعة، وإعادة تقطيع، ومراجعة، وZIP احتياطية. يعمل مسار ZIP الأصلي من الكمبيوتر إذا منع المتصفح loopback. يظل إنشاء الدرس ونشره أمرين منفصلين عبر Backend الحالي.

هذه النسخة **تحتاج نصًا إنجليزيًا مطابقًا للصوت**. تستعمل WhisperX لمحاذاة النص وتقسيم الصوت؛ لا تولّد Transcript أوVocabulary/Quiz أوشات. صفحة Teacher الخاصة بمتابعة الطلاب لم تحصل على صلاحيات Admin. لم يتغير V1 أوقواعد المشروع المعتمدة أونموذج SQL أوMigration.

## ما أثبتته الاختبارات

- الاتصال يستمع إلى `127.0.0.1` فقط، ويتحقق من Host وOrigin ومفتاح Bearer خاص بالأداة؛ لا cookie الموقع أوCSRF أوجلسة الدخول تُرسل للأداة، ولا CORS wildcard. بيانات الربط لا تحتوي كلمة مرور الموقع.
- الحسابات والأصول لها ملفات محلية منفصلة؛ المسودة المنقولة بين الصفحتين تُستهلك فقط لحسابها. ملف الربط الواحد يدعم حسابًا وأصلًا واحدًا عند التشغيل.
- قراءة الحالة والنتيجة وفتح الصفحة لا تحفظ ولا تنشر درسًا. المعالجة والمراجعة وإعادة التقطيع تنتج ملفات محلية فقط. أول كتابة إلى API الموقع تأتي من ضغط «احفظ الدرس»، والنشر ضغط منفصل.
- تكرار إنشاء نفس المهمة لا يضاعفها؛ اختلاف محتوى نفس المعرف يرجع conflict. توجد مهمة نشطة واحدة، وتظل محجوزة حتى خروج worker الملغى. إعادة تشغيل الأداة لا تعيد معالجة المهمة المتوقفة تلقائيًا.
- تعديل غير صالح لأي مقطع لا يغير المقاطع السابقة. توقيت WAV محسوب بدقة frame؛ لم يعد تقريب نهاية آخر frame يتجاوز مدة الصوت.
- ZIP غير متوقعة أوذات traversal/تكرار/CRC خاطئة أوWAV/hash غير متطابق تُرفض. استيراد ZIP لا يحفظ درسًا، ويتطلب تأكيد مراجعة الصوت والنص.
- صفحة الطالب لا تتصل بالخدمة المحلية ولا تنزل حزمة الأداة. وُجدت المعالجة في صفحة Admin lazy؛ فحص desktop/mobile شمل عدم وجود overflow أفقي.
- السجلات التي فُحصت لا تحتوي token أوالنص أوالعنوان أومسار ملفات الجهاز؛ تستخدم معرفات وحجمًا ومدة وأكواد أخطاء.

## تجربة المحرك الحقيقي

شُغّل `worker.py` الإنتاجي في process منفصلة على CPU، باستخدام Torch/torchaudio 2.8.0 CPU وWhisperX 3.8.6 وTransformers 4.57.1 وNLTK 3.9.2. نُزّل نموذج `WAV2VEC2_ASR_BASE_960H` الفعلي (نحو 360 MiB) وبيانات `punkt_tab` أثناء warmup.

العينة: صوت إنجليزي صناعي عبر FFmpeg/flite، مدته **1.875 ثانية**، والنص المقدم مطابق له، سطران. خرج مقطعان WAV PCM16 mono 16 kHz؛ تحققت bytes وSHA-256 وحدود المدة وتطابق عدد frames. ظل `reviewRequired=true`.

```json
{
  "exitCode": 0,
  "durationMs": 5838,
  "peakResidentMiB": 1182.5,
  "sourceSeconds": 1.875,
  "segments": 2,
  "reviewRequired": true,
  "validated": true

```

هذا قياس عينة قصيرة في هذه البيئة، ولا يقدّر وقت أودقة أوميموري درس 10 دقائق على كمبيوتر Windows. runtime الاختبار المعزولة جهزت اعتماديات محاذاة الصوت؛ لم تختبر تنزيل dependency graph الكاملة من Windows installer. لا GPU ولا Whisper transcription ولا diarization استُخدمت.

## تصحيح Backend وإعادة البناء

أول بناء .NET لهذه النسخة كشف `CS4007` داخل `SameAudioAsync`: تحويل نتيجة hash الأولى إلى `ReadOnlySpan<byte>` أثناء انتظار hash الثانية. أُصلح بحساب `incomingHash` و`storedHash` كمصفوفتين أولًا، ثم مقارنة `CryptographicOperations.FixedTimeEquals` بعد اكتمال await. استمر SHA-256 والمقارنة ثابتة الزمن، دون تغيير قواعد إعادة الطلب أومخطط SQL. أعيد بناء الحل ونجح بصفر تحذيرات.

هذا build فقط؛ لا تثبت هذه النتيجة إعادة الطلب عبر API المصادق أوSQL. يلزم إجراء هذه الفحوص على قاعدة V2 التجريبية كما في دليل إنشاء الدرس.

## عوائق البيئة أثناء التشغيل

رفض sandbox إنشاء sockets في المحاولة الأولى لاختبار Python، وجلب Google Fonts في build، واتصالات عمال MSBuild المحلية. أعيدت الأوامر بصلاحية تشغيل مناسبة ونجحت دون تعديل اختبارات لتجاوزها. تنزيل Chromium الحالي من CDN فشل؛ استُخدم Chromium **134.0.6998.35** من أرشيف Playwright الرسمي مع executablePath، دون تغيير Playwright 1.63.0 في المشروع. طلب إذن Local Network Access في Chrome الحديث لم يُختبر.

صُحح عطل في fallback Python أثناء التنفيذ: متغير محلي كان يحجب اسم module `http`؛ ثم اجتاز مسار ZIP HTTP الحقيقي. وأُصلحت تسمية ملف ZIP في اختبار Playwright وصياغة إشعار النشر المتوقعة في الاختبار. لا تُحسب المحاولات الفاشلة PASS؛ الجدول يسجل إعادة التشغيل النهائية الناجحة.
