# Day 2 — Groups foundation (2026-09-28)

## الفكرة بالمثال

لو طالب في المجموعة «أ» ثم نقله Admin إلى «ب»، نقفل عضوية «أ» بتاريخ النهاية ونضيف عضوية «ب». نحتفظ بالسجل القديم. الطالب الجديد قد لا تكون له عضوية فعّالة أصلًا. قاعدة البيانات تمنع وجود عضويتين مفتوحتين للطالب نفسه حتى عند وصول طلبين معًا.

## ما تم تجهيزه

- `StudyGroups` و`StudentGroupMemberships` محفوظتان في SQL عبر EF Core؛ لا localStorage ولا إنشاء مجموعات عند تسجيل الدخول.
- ترحيل `20260928154813_AddGroupsFoundation` يضيف جدولين فقط، علاقات بدون حذف متسلسل، وقيدًا فريدًا مفلترًا على `StudentId` حيث `EndedAtUtc IS NULL`، وشرط تاريخ النهاية. لا يغير جداول Identity الحالية.
- API تحت `/api/admin/groups` لدور Admin: قائمة مجموعات، إنشاء مجموعة، بحث الطلاب ببداية البريد، نقل/فك إسناد، وتاريخ عضوية الطالب. القوائم محدودة الصفحات. الكتابة تتطلب CSRF وتُحدّ بطلبات لكل Admin.
- النقل يتطلب `expectedMembershipId`. التكرار لنفس المجموعة لا يضيف صفًا جديدًا؛ إذا اختلفت العضوية الحالية يرجع `409 membership_changed`. يغلق الصف القديم قبل إدراج الجديد داخل معاملة `Serializable`.
- إنشاء المجموعة يحمل `requestId` ثابتًا عند إعادة المحاولة؛ القيد الفريد يمنع إنشاء مجموعتين لنفس الطلب، وطلب مكرر بنفس الاسم يرجع المجموعة الموجودة.
- صفحة `/admin/groups` الحالية تعرض بيانات API، وتطلب تأكيد النقل، وتُظهر الأخطاء والتاريخ. لا تغيّر الـLayouts أوالمسارات.

## التحقق اللازم قبل اعتبار الشريحة منتهية

1. على جهاز به .NET SDK 10 وSQL Server اختباري: `dotnet build backend/ShadowingEnglish.sln`.
2. راجع الترحيل مع `dotnet ef migrations has-pending-model-changes --project backend/ShadowingEnglish.Infrastructure --startup-project backend/ShadowingEnglish.Api`. الترحيل هنا مُعد يدويًا لأن SDK غير متوفر في بيئة العمل الحالية؛ أعِد توليده بأداة EF قبل تطبيقه لو ظهرت أي فروق.
3. راجع SQL script قبل أي `database update`. تطبيق الترحيل قرار صريح على قاعدة اختبار/تطوير فقط؛ لا تشغيل ترحيلات تلقائيًا ولا تعديل قاعدة V1.
4. API عمليًا: anonymous → `401`، Student → `403`، Admin بلا CSRF على POST/PUT → `400`، Admin ينشئ مجموعة ويظهرها GET دون كتابة جانبية.
5. كرر POST إنشاء مجموعة بنفس `requestId` بعد انقطاع الرد؛ يجب أن يرجع نفس المجموعة. جرّب نفس المعرّف مع اسم مختلف؛ يجب أن يرجع تعارضًا بدل إنشاء أخرى.
6. بطالب موجود فعليًا: بدون مجموعة → إسناد «أ» → تكرار الطلب دون عضوية ثانية → نقل إلى «ب» مع حفظ «أ» في التاريخ → طلب قديم `409` → فك الإسناد مع بقاء السجل. طلبان متزامنان يجب ألا يتركا عضويتين فعّالتين.
7. اختبر الشاشة على المحمول ولوحة المفاتيح، وافحص Diagnostics للعمليات الناجحة والفاشلة دون أسماء/بريد/أسرار في السجلات.
