# تقليل استعلامات تحقق الطالب في مسارات الدرس — #24

التاريخ: 23 أكتوبر 2026. تحسين جزئي.

كانت مسارات المنهج وملخص الدرس والصوت تتحقق من الطالب بقراءة الحساب عبر
`UserManager` ثم فحص الدور، ما يضيف أكثر من استعلام لقاعدة البيانات إلى
كل طلب. أصبح التحقق من وجود الحساب ودور Student الحي استعلامًا واحدًا
بربط جداول المستخدمين والأدوار. أبقينا التحقق المباشر من قاعدة البيانات
حتى يسري سحب الدور على جلسة مفتوحة فورًا؛ نجح اختبار إزالة دور الطالب
ثم محاولة قراءة المنهج بنفس cookie.

أعدنا اختبار 3000 حساب وجلسة مستقلة على TestServer وSQL Server المحلي.
تسجيل الدخول بقي محدودًا بـ300 طلب متزامن، ثم نفذنا 3000 طلب متزامن
لكل مسار قراءة:

| المسار | P95 قبل | P95 بعد | أخطاء بعد |
| --- | ---: | ---: | ---: |
| المنهج | 7513 ms | 6226 ms | 0 |
| ملخص الدرس | 6198 ms | 4962 ms | 0 |
| الصوت | 7259 ms | 6056 ms | 0 |

الزمن الكلي بعد التغيير كان 6761 ms للمنهج، و5456 ms للملخص، و6966 ms
للصوت. هذه عينة واحدة لكل حالة على جهاز التطوير؛ تُظهر اتجاهًا مفيدًا
ولا تثبت نسبة تسريع ثابتة. ما زال P95 مرتفعًا لتجربة سريعة عند 3000
طلب متزامن. يلزم قياس بقية استعلامات الصفحات والاختبار على الاستضافة
النهائية. لم تُحذف أي بيانات أو ملفات؛ أضاف الاختبار حسابات إلى قاعدة
اختبار معزولة.

```powershell
& .\.local\tools\dotnet-10.0.402\dotnet.exe run --project tests/ShadowingEnglish.MediaChecks/ShadowingEnglish.MediaChecks.csproj -c Release -- --security-check
& .\.local\tools\dotnet-10.0.402\dotnet.exe run --project tests/ShadowingEnglish.MediaChecks/ShadowingEnglish.MediaChecks.csproj -c Release -- --processor-student-read-load '<manifest path>' 3000 300 3000
```
